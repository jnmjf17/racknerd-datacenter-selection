## 大陆用户怎么选：DC-02、DC-03 和圣何塞到底差在哪

西海岸三个节点的定位并不一样，混为一谈会选错。

**洛杉矶 DC-02 是首选，但有两个门槛。** 它托管在 Multacom 机房，走 Asia Optimized 亚洲优化网络，接入中国电信、联通、网通，三网基本直连；电信走 163 优化线路，联通走 AS4837。测试 IP 在国内主要城市的正常时段延迟约 150–180ms，晚高峰丢包率也低于一般美西机房。这个数字谈不上惊艳，但在美西 VPS 里算稳定的一档。门槛一是它历史上只对 2GB 内存及以上的套餐开放——官方促销公告原话是"Los Angeles DC-02 location is back in stock for VPS and available for PIDs 904 to 907"，也就是 2GB 及以上的方案；1GB 低配的下拉框里看不到 DC-02。门槛二是库存：每次大促（新年、黑五、双 11）重新放货，通常几天内被抢空。你要做的就是在购物车「Configurable Options」的机房下拉框里确认它是否可选，以实际显示为准。

**洛杉矶 DC-03 和 DC-02 不是同一个物理机房。** DC-03 在洛杉矶市中心另一处设施，网络接 Cogent 等运营商，提供美国原生 IP，并且开放 25 端口。三网往返也基本直连，只是优化程度不如 DC-02。需要发邮件（25 端口）或者原生 IP 做某些服务的人，DC-03 反而是正确答案，别只因为延迟略高就排除它。

**圣何塞是预算方案。** 三网往返直连，电信去程直连延迟约 160ms，联通走 AS4837 表现稳定，库存充足，1GB 小机器也能选。移动用户个别节点有绕路，纯移动网络建议先 ping 再定。西雅图对联通用户相对友好，延迟比圣何塞略高，比东海岸好很多，属于备选。

东海岸（纽约、新泽西、阿什本、亚特兰大）到国内延迟普遍比西海岸高出 60–100ms，晚高峰还容易绕路丢包。除非你的用户在欧美，否则没必要为了同样的价格选东边。有第三方实测案例很能说明问题：同一家、同样的价格，一位东南亚用户对比洛杉矶 DC-02 和新泽西，延迟是 138ms 对 207ms——不看数据凭感觉选，一年就多背 70ms。

## 下单前怎么实测：五分钟 Looking Glass 流程

实测顺序是 ping → MTR → 测速文件，五分钟够用：

1. 打开候选机房的 Looking Glass 页面，点 "My IP" 按钮自动填入你当前的公网 IP
2. 先跑 Ping，记下平均往返。50ms 以下体感即时，50–100ms 对多数 Web 应用够用，150ms 以上交互操作会开始卡
3. 晚高峰（20:00–23:00）再测一次。这个时段的丢包和延迟才代表真实体验，白天测的数字经常是骗人的
4. ping 偏高时改跑 MTR，它会显示每一跳的丢包，帮你判断是距离问题还是路由问题
5. 最后下载候选节点的 100MB 测试文件计时，算出实际吞吐量

低延迟不等于下载速度快，实际速度还取决于带宽和晚高峰丢包，所以第 5 步不能省。另一个常见错误：纠结两个节点之间 5ms 的差距。人眼看不出区别，Looking Glass 的价值是帮你避开 50ms 级别的选择错误。但 30ms 对 180ms 的差距是真实信号，别为了几美元的差价选延迟差一倍的机房。
